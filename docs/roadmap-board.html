P0必修A1

成长记忆从未真正生成（招牌功能是死的）

现状data/memory.md 是 0 字节，但 data/daily 里躺着 数百条历史对话。
为什么是问题_summarize_yesterday() 只在 _check_daily_reset() 里被调用，而后者又只在 _flush() 里被调用 ——也就是「只有在准备发一条回复、且刚好跨天」时才会沉淀记忆。机器人一暂停、或那天没触发回复，记忆就永远不更新。而且它只看「昨天」一天。
怎么做① 抽一个独立的 memory_worker 线程，启动即扫描 data/daily 下所有缺摘要的日期并按序补跑；② 补跑加节流（每次启动最多补 N 天，避免一口气烧掉一堆 token）；③ 面板加「立即沉淀记忆」按钮 + 进度显示；④ 补跑结果写进事件时间线。
预期效果「跨天成长」这个核心卖点真正生效；AI 终于能记住她前几天在忙什么、心情如何。
工作量 中（1–4h）风险 低（AI 调用失败已有兜底，补跑失败不影响主流程）
P0必修A2

main.py 的 PID_PATH 未定义，bot.pid 永远写不出来

现状main.py 第 126 行用 PID_PATH 写 bot.pid，但全文件从未定义这个常量。
为什么是问题NameError 被 try/except Exception 静默吞掉，所以没有任何报错。后果：面板 stop_bot() 的「心跳文件失效时的兜底路径」永远拿不到 PID，只能靠猜。
怎么做① 补上 PID_PATH 常量；② 把这一段的 except 从「静默 pass」改成「log.warning」，避免同类问题再被吞掉；③ 顺手接 core.atomicio 原子写。
预期效果关停/重启机器人的可靠性提升，不再出现「关不掉」或「误杀」的玄学问题。
工作量 小（<1h）风险 极低
P0必修A3

schedule.json 读-改-写非原子，面板与 bot 同时写会丢任务

现状_run_job() 里是 load → 改 last_run → dump；面板 save_schedule() 也是整文件覆盖。
为什么是问题两个进程（面板 / bot）加两个线程（主循环 / 定时任务线程）都在写同一个文件，没有任何锁。经典后果：定时任务刚标记「今天已执行」，面板改个开关就被覆盖回去，于是同一条早安一天发两次。
怎么做① 统一走 core.atomicio（tmp → fsync → replace）；② 加一个跨进程文件锁（.schedule.lock）；③ 写之前重新读一次（read-modify-write 竞态窗口最小化）。
预期效果定时任务不再重复触发/丢失，配置改动不丢。
工作量 小（<1h）风险 低
P0必修A4

main.py 完全没接入 2.0 的 core 模块

现状控制文件、心跳、每日日志、定时任务全是裸 open 写；路径硬编码 BASE_DIR。
为什么是问题2.0 给面板做了原子写 + 备份 + 统一路径解析，bot 侧还是 1.0 写法。两边对同一批文件的写入策略不一致，是最容易出诡异 bug 的地方。
怎么做① main.py 引入 core.atomicio / core.paths / core.proclog；② 日志接入 rotate_if_needed；③ 路径走 _resolve_base_dir 同一套逻辑。
预期效果bot 与面板行为一致；崩溃/断电不再写坏控制文件和配置。
工作量 中（1–4h）风险 中（改动面较大，建议配回归测试）
P0必修A5

历史日志没有补跑通道，数百条对话白白浪费

现状历史每日日志一条都没转成记忆，且现在没有任何入口能补。
为什么是问题见 A1：补跑能力不存在，不只是没触发。
怎么做随 A1 一起做：补跑工具独立成 CLI（python main.py --backfill-memory --days 14），面板也能点。补跑时按天倒序、每天一次 AI 调用、失败可重试。
预期效果现有历史对话一次性变成可用的长期记忆，AI 立刻变「懂事」。
工作量 小（<1h）风险 低
P1体验B1

回复预演（干跑）：改完人设卡先看它怎么回

现状改人设卡 / 关系档案只能盲改，要验证就得等她真发消息，或者直接拿真人做实验。
为什么是问题这是迭代语气的最大障碍。改一个字要等下次真实对话才知道效果，试错成本极高。
怎么做面板加「预演」输入框：输入她可能说的话 → 服务端用真实 system prompt + 当前上下文生成回复，**只返回不发送**；支持一次生成 3 个候选（temperature 微调）供挑选；可指定「假装她刚连发这三条」测试 burst 聚合效果。
预期效果调语气从「靠运气」变成「所见即所得」，半小时能调完过去一周的活。
工作量 中（1–4h）风险 低（只是多调一次 API，不发送）
P1体验B2

主动发起：从「自动回复」进化成「会找你说话」

现状机器人只能被动应答，她不说话就永远沉默。
为什么是问题真人恋爱里主动问候、主动分享是刚需。纯被动的机器人聊久了会觉得「他从不找我」。
怎么做① 沉默时长阈值触发（如 6 小时，可配）；② 时间窗限制（只在 9:00–23:00，且避开她可能在忙的时段）；③ 一天最多主动 1–2 次，且与定时任务互斥；④ 主动内容由 AI 结合记忆生成（「今天考试加油」而不是固定早安）；⑤ 主动失败的兜底：她没回就不追加。
预期效果从「自动回复工具」变成「陪聊」，这是体验上最大的一档跃升。
工作量 大（>4h）风险 中（主动发消息风险较高，必须有开关 + 次数上限 + 时间窗三重护栏）
P1体验B3

情绪与敏感场景分级处理

现状只在 prompt 里写了一句「涉及吵架/道歉/转账就拖延话术」，没有工程兜底。
为什么是问题prompt 里的规矩模型不一定遵守，一旦在吵架时回了个玩笑话，后果比不回严重得多。
怎么做① 发送前用一个轻量分类器（关键词 + 可选小模型）打标：争吵 / 难过 / 道歉 / 生病 / 金钱 / 承诺 / 告别；② 命中高敏标签 → 强制切换到「保守应答模式」（更短、更温柔、不撩、不玩笑），或直接转人工（通知你 + 暂停自动回复）；③ 命中「承诺/金钱」→ 直接拦截不发送，转给你。
预期效果把「AI 说错话」的尾部风险从不可控变成可控。
工作量 中（1–4h）风险 低（只做收敛不做增强，误判代价小）
P1体验B4

回复质量反馈闭环（赞 / 踩）

现状没有任何「这条回得好不好」的记录，模型永远不知道自己哪儿不对。
为什么是问题没有反馈就没有优化方向，只能靠你凭感觉改 prompt。
怎么做① 面板每日记录里每条 AI 回复加赞/踩按钮；② 写入 data/feedback.jsonl（含原文、回复、时间戳、标签）；③ 面板显示近 7 天「踩率」曲线；④ 踩的样本自动进入「待复盘」列表，供参谋分析；⑤ 长期可作为 few-shot 负样本，或微调依据。
预期效果有了可量化的质量指标，优化不再靠拍脑袋。
工作量 中（1–4h）风险 低
P1体验B5

语气强度滑杆（不写 md 也能调风格）

现状要调语气必须改 persona.md 或改 prompt 源码，门槛高。
为什么是问题很多微调需求其实只是「再撩一点 / 别这么油 / 话再少点」，不值得去改长文本。
怎么做面板加一组滑杆：撩的程度、话多话少、表情使用频率、玩笑比例、关心直白度。存进 config.json 的 style_tuning，PromptBuilder 按档位拼接对应指令段。
预期效果调风格从「写作文」变成「拧旋钮」，随时可回滚。
工作量 中（1–4h）风险 低
P2体验B6

「对方正在输入」感知与抢答抑制

现状对方连发时靠 settle_seconds 攒 3 秒再回，但她边打字边发时仍可能抢答。
为什么是问题真人不会在你还没说完时插话。抢答是很强的「这不是真人」信号。
怎么做若后端能拿到「正在输入」状态（wxauto/wechatauto 部分版本可得），则延长 settle；拿不到就用启发式：最后一条消息 <2 秒且连续多条 → 再等一轮。
预期效果对话节奏更像真人。
工作量 小（<1h）风险 低（后端不支持时优雅降级）
P2体验B7

更多消息类型：语音 / 表情包 / 视频 / 红包 / 撤回

现状只处理文本和图片；语音、表情包、视频、红包、撤回一律被忽略或当成空消息。
为什么是问题她发个表情包或语音，机器人不接话，对话就断了。
怎么做① 表情包：取包名/包描述当文本处理（「[表情包: 熊猫头-无语]」）；② 语音：若后端能拿到转写文本则处理，拿不到则回一句自然的兜底（「在忙，晚点听」）；③ 红包/转账：只记日志不回复；④ 撤回：记为「她撤回了一条」，不追问。
预期效果覆盖真实聊天的长尾场景，不再出现「她发了东西机器人没反应」的尴尬。
工作量 中（1–4h）风险 中（依赖后端能力，需要按后端做能力探测）
P2体验B8

多监听对象各自独立的配置

现状config.listen 是个列表，但定时任务、早安消息只发给第一个（_sched_target 直接 return 第一个）。
为什么是问题现在只有一个对象所以没暴露问题，一旦加第二个，定时任务就会发错人。
怎么做listen 改成对象数组：{name, 人设覆盖, 定时任务, 冷却, 开关}；面板按对象分页管理；PromptBuilder 按对象取不同的人设与关系档案。
预期效果支持多对象而不用复制一份部署。
工作量 大（>4h）风险 中（数据结构变更，需要迁移旧 config）
P1记忆C1

三层记忆：日摘要 → 周摘要 → 长期画像

现状只有一层日摘要，且 keep_days=3（只带最近 3 天）。
为什么是问题3 天太短，「她在备考」「她怕冷」这类长期事实会随滚动窗口丢失；而只存日流水又会让 system prompt 越堆越长。
怎么做① 日摘要（每天）→ ② 周摘要（每周把 7 条日摘要压成一段）→ ③ 长期画像（结构化：喜好/禁忌/日程/约定，存 data/profile_facts.json）；system prompt 只带「周摘要 + 长期画像」，token 可控且信息密度更高。
预期效果记得住长期事实，同时 system prompt 不膨胀。
工作量 大（>4h）风险 中
P1记忆C2

从「流水账总结」改成「事实抽取」

现状每日摘要 prompt 是「用 3-5 句话总结要点」，产出的是叙事流水账。
为什么是问题流水账重复率高（每天都说「她很累」），占 token 却没增量信息；真正有用的是新事实。
怎么做① 摘要 prompt 改为抽取结构化事实（人物/事件/情绪/约定/偏好），只写「新增或发生变化」的；② 写入前与已有画像 diff，重复的丢弃、冲突的标记待你裁决；③ 结果以提案形式给你过目。
预期效果记忆从「越攒越啰嗦」变成「越攒越精准」。
工作量 中（1–4h）风险 中
P1记忆C3

人设卡自动再蒸馏的闭环

现状tools/distill_persona.py 要手动跑，且依赖 chat_history.json（8/23 的快照），之后再没更新过。
为什么是问题你的说话习惯会被 AI 的回复反向影响（回声室），也会随时间变化。人设卡是一次性产物，会越来越失真。
怎么做① 每周自动用「主人手动发的消息」（is_ai=False，看 main.py 已有这个标记）重新蒸馏；② 新旧人设卡 diff 生成提案，你点头才覆盖；③ 蒸馏输入排除 AI 代发内容，防回声室污染。
预期效果人设卡能跟上你的真实变化，且不引入 AI 自我模仿的污染。
工作量 中（1–4h）风险 低（有提案确认机制兜底）
P1记忆C4

提案中心减负（现在积压 23 条待处理）

现状proposals.json 里 38 条，其中 23 条 pending，且没有批量操作、没有过期、没有去重。
为什么是问题提案一多就没人看了，自进化机制等于失效。
怎么做① 批量通过/拒绝/归档；② 超过 30 天未处理自动归档并可一键清空；③ 相似提案合并（按内容指纹去重）；④ 标注来源（哪天的哪段对话触发的），可跳转回看；⑤ 按类型分栏（人设/关系/事实/提醒）。
预期效果提案中心从「越积越焦虑的收件箱」变回有用的工具。
工作量 中（1–4h）风险 低
P2记忆C5

每日回顾卡片

现状面板的「今日聊天记录」是原始 jsonl 文本，没有可读性。
为什么是问题你想知道「今天她心情怎么样、聊了什么」，现在得自己读流水。
怎么做每天自动生成一张卡片：她的情绪曲线、今天的主要话题、新产生的事实、待办约定；放在面板首页，可翻历史。
预期效果一眼掌握今天聊得怎么样。
工作量 中（1–4h）风险 低
P2记忆C6

约定与纪念日提醒

现状relationship.md 里写着「8.29 飞B城」这类约定，但纯文本，模型不一定记得住，你也没有提醒。
为什么是问题约定是恋爱里最不该忘的东西，漏掉一次很伤。
怎么做① 从 relationship.md / 记忆里抽取带日期的约定，存成结构化事件；② 面板「即将到来」列表 + 到期前提醒；③ 可选：让 AI 在当天自然提起（可关）。
预期效果不再错过重要日子。
工作量 中（1–4h）风险 低
P1运维D1

Token 与成本统计

现状完全不记录 token 消耗，也不知道每天花了多少钱。
为什么是问题虽然 DeepSeek 便宜，但 burst 聚合 + 长 system prompt + 视觉识别都在吃 token，一旦配置不当（比如补跑记忆一口气跑 30 天）可能意外烧钱。
怎么做① ai_client 记录每次调用的 usage（prompt/completion tokens）；② 写入 data/usage.jsonl；③ 面板显示：今日/本月 token、估算花费、平均每次回复成本；④ 超过阈值告警。
预期效果成本可见，心里有数。
工作量 小（<1h）风险 低
P1运维D2

事件时间线（关键动作审计日志）

现状出了事只能翻 bot.log 和 ui_server_startup.log，两处还不同步。
为什么是问题「她昨天说机器人没回她」这种问题，需要的是一条按时间排好的、跨 bot 和面板的事件流。
怎么做统一写 data/events.jsonl：启动/停止/暂停/恢复/改人设/通过提案/定时任务触发/AI 失败/微信掉线/自动重连。面板加「事件」标签页，可按类型和日期过滤。
预期效果排障时间从「翻日志猜」降到「看时间线」。
工作量 中（1–4h）风险 低
P1运维D3

崩溃自愈：bot 意外退出后自动拉起

现状bot 挂了就是挂了，面板只显示「未运行」，等你发现。
为什么是问题微信掉线、后端异常、内存问题都可能让它半夜挂掉，你第二天才知道。
怎么做① 面板检测心跳超时 → 按策略自动重启（可开关）；② 重启次数上限（如 10 分钟内最多 3 次），超过则停止并告警，避免重启风暴；③ 每次重启写事件时间线。
预期效果夜里挂了也能自己爬起来，不用第二天才发现「它一整天没回她」。
工作量 中（1–4h）风险 中（必须有次数上限，否则会刷屏重启）
P1运维D4

微信掉线自动重连 + 明确告警

现状后端 poll 报错只 log.error，wechat_ready 不会置回 False，面板一直显示「已连接」。
为什么是问题状态显示是假的：实际上已经收不到消息了，但面板骗你说一切正常。
怎么做① 连续 N 次 poll 失败 → wechat_ready=False 并写事件；② 自动重连（退避重试，最多 M 次）；③ 失败则通过文件传输助手 + 面板红条告警；④ 面板区分「已连接 / 重连中 / 已断开」。
预期效果状态显示终于可信。
工作量 中（1–4h）风险 低
P2运维D5

延迟与失败率看板

现状没有任何性能指标。
为什么是问题「她抱怨回复慢」时无法判断是 AI 慢、后端慢还是网络慢。
怎么做记录三段耗时：收到消息 → AI 返回 → 发送成功；面板画 P50/P95 折线；同时统计 AI 失败率、图片识别成功率。
预期效果性能问题可定位。
工作量 小（<1h）风险 低
P2运维D6

一键备份 / 恢复快照

现状人设卡、记忆、关系档案散落在 data/ 下，.bak 只有最近 5 份且是按文件分散的。
为什么是问题换电脑、误删、改崩了想回滚——现在没有可靠的整体快照。
怎么做① 面板「导出快照」打包：config(脱敏) + persona/relationship/memory + style_profile + proposals + daily；② 「导入快照」可整体恢复（覆盖前自动再打一份）；③ 支持定时自动快照（每日 1 份，保留 30 天）。
预期效果误操作可回滚，换机可迁移。
工作量 中（1–4h）风险 中（导入会覆盖数据，必须二次确认 + 自动预备份）
P2运维D7

发送前内容审查（防乱承诺 / 防暴露身份）

现状AI 生成什么就发什么，唯一约束是 prompt 里的铁律。
为什么是问题模型偶尔会违规。一旦发出「明天我去找你」「我给你转 5000」或者一句「作为 AI」，代价远大于不回复。
怎么做① 发送前过规则引擎：承诺类（见面/转账/买/答应）、身份泄露（AI/机器人/助手/作为）、越界亲密、敏感信息；② 高敏命中 → 拦截不发送 + 通知你 + 记事件；③ 中敏命中 → 改写为安全话术后再发；④ 规则可配，命中记录可见。
预期效果把最坏情况兜住。这是「敢让它跑」的前提。
